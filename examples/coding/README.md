# Captured coding task — experimental v0.2

Repair a small transaction summarizer: trim categories, sum integer amounts and
refunds, reject malformed inputs, and sort the report. Three files may change.
The baseline, tool proposals, task policy and checker scope are frozen before
execution in `task.json` and `task.sha256`.

From a clean Git checkout at the repository root, as an ordinary user
([build and platform prerequisites](../../INSTALL.md#prerequisites-and-platforms)):

```sh
./realm coding-demo --output /tmp/realm-coding-first --disposable-replay
```

Choose a new output directory each time. Omit `--disposable-replay` for inspection
only. Source installation uses the existing locked Rust build (Rust/Cargo 1.97.1,
a C compiler and libclang); Python uses only its standard library. No model API,
credentials, private repository or prebuilt binary is needed. The proposals are
saved inputs, not a fresh autonomous agent solution.

macOS requires `/usr/bin/sandbox-exec`. Linux requires **x86_64**, `/usr` Python,
bubblewrap, and permitted unprivileged namespaces. Install those system
prerequisites through your normal administrator workflow. The program refuses
unsupported environments; do not use root, privileged containers, or disable
security controls to force it to run. Codespaces/container availability does not
establish these capabilities. The existing devcontainer supports artifact work;
it is not qualified for this sandboxed example.

## What actually happens

1. The existing worker processes bounded `list/read/write/check/finish` requests
   in a fresh workspace, journals their order and before/after hashes, and refuses
   an out-of-scope path. Candidate Python runs in the existing OS child sandbox.
2. A separate transcript auditor checks hash linkage, task/source pins, supported
   effects and terminal closure. A separate task referee runs fixed and seeded
   cases, checks the API and report, and tests discrimination against the broken
   baseline. These are bounded tests, not universal Python correctness.
3. The existing Rust encoder creates `capture.realm` from captured writes and the
   six original evidence members. A separate receiver process reopens it and
   reconstructs the artifact against task-derived expectations supplied separately from the artifact. These local
   pins are generated by the harness, not independently provisioned production trust.
4. The receiver returns **INCOMPLETE / NONE** and has no destination parameter.
   A separate auditor checks the transcript extracted from the actual archive.
5. Only your explicit replay flag creates three mode-0600 files in a fresh
   disposable child directory. An independent process reopens and checks their
   hashes, modes and file set. A protected canary must remain unchanged.

Inspect `RESULT.json`, `receiver.stdout`, `receiver-independent-audit.stdout`,
`disposable-final-state.stdout` and `capture.realm` in your chosen directory.
The harness also requires missing-capture, forbidden-path, projection-substitution,
post-closure-event, forged-authentication, tampered-artifact, cross-run and missing-pin inputs to refuse
without creating artifacts. Failed runs retain `FAILURE.json`, partial tool responses
and stage logs; no `RESULT.json` success is issued. Worker writes, complete response
frames and terminal EOF all have deadlines. Stage logs are limited to 2 MiB.
Disposable verification uses held directory-relative descriptors and rejects links,
nonregular files, changed identities and unexpected permissions.

To inspect your generated artifact:

```sh
./realm inspect /tmp/realm-coding-first/capture.realm --json
./realm verify /tmp/realm-coding-first/capture.realm --require-execution --json
```

Expect content VALID, then execution INCOMPLETE (intentional exit 3).

For an already built standalone checker:

```sh
python3 examples/coding/run.py --checker target/debug/realm-artifact \
  --output /tmp/realm-coding-second --disposable-replay
```

`realm-artifact inspect-development-realm` requires the artifact BLAKE3 pin,
`expectations.json` and its BLAKE3 pin; inspect exits **3** for INCOMPLETE. Pins
establish bytes and expected labels, not trusted execution identity. The Rust
receiver reconstructs supported writes; the separate Python auditor checks the
SHA256 transcript chain. Neither component authenticates the controller.

## Limits and extension points

You can modify a component on a branch and regenerate task/source pins explicitly
and commit the selected source before another experiment. See the
[explicit pin-update commands](../../CONTRIBUTING.md). Supply an independent
`--task-sha256` when using a custom task file. The supplied example deliberately fixes the three paths and
policy; it is not a general shell runner. Do not feed it unreviewed proposals on
a sensitive host: the controller and OS remain trusted, unqualified components.

Capture covers worker-mediated operations and bounded checker observations.
Planner inputs, complete syscalls, hidden channels, hostile host interference,
measured runtime identity and production enforcement remain unestablished.
`VALID` content integrity never means execution `ACCEPT`. No trust installation,
qualified native launch, canonical production publication or protected destination
application is included. Historical benchmark A/B results are unchanged; this
example is integration evidence, not a new benchmark score.

Contributor regression command (requires the sandbox prerequisites above):

```sh
python3 tools/dev.py coding --output /tmp/realm-coding-regression
```

An unavailable sandbox is a refused/NOT_RUN execution, not a passing coding lane.

`coding_broker_client.py` exposes the existing bounded packet framing/send
protocol for local Rust broker regression tests. Acknowledgment remains
DEVELOPMENT/NONE; guest connectors and native launch are not included.

[Recorded acceptance](ACCEPTANCE.json) distinguishes the tested source revision,
local checks, ignored tests and NOT_RUN stages. Fresh nonces and recorded seeds
make run artifacts differ bytewise; reproduce the checks, not a fixed artifact hash.
